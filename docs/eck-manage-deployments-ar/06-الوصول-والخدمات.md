# 6 — الوصول إلى الخدمات (Accessing services)

**الرابط الرسمي:**  
<span dir="ltr">https://www.elastic.co/docs/deploy-manage/deploy/cloud-on-k8s/accessing-services</span>

## الفكرة

ECK يوفّر الوصول لـ <span dir="ltr">Elasticsearch</span> و<span dir="ltr">Kibana</span> (وغيرها) عبر **خدمات Kubernetes**.

الافتراضي:

- **مصادقة أساسية** (مستخدم <span dir="ltr">elastic</span>)
- **TLS** على HTTP
- تشفير داخل كلاستر Elasticsearch (transport)

## استرجاع كلمة مرور `elastic`

السر اسمه: `<اسم-الكلاستر>-es-elastic-user`

```bash
kubectl get secret hulk-es-elastic-user -o go-template='{{.data.elastic | base64decode }}'
```

تحذير: لا تنسخ Secret كما هو إلى namespace آخر دون فهم **Owner References** (قد يسبب مشاكل).

لمزيد من التفاصيل: **Built-in users** و **Users and roles** في [07-ضبط-النشر.md](./07-ضبط-النشر.md).

## أسماء الخدمات ونوعها

لكل مورد، المشغّل ينشئ خدمة HTTP اسمها نمطياً:

<span dir="ltr">&lt;name&gt;-es-http</span> أو <span dir="ltr">-kb-http</span> أو <span dir="ltr">-apm-http</span> …

النوع الافتراضي: **ClusterIP** — متاح **داخل** الكلاستر فقط.

```bash
kubectl get svc
```

## فتح وصول من الإنترنت (LoadBalancer)

في المواصفة:

```yaml
spec:
  http:
    service:
      spec:
        type: LoadBalancer
```

ينطبق على أي <span dir="ltr">kind</span> من موارد Elastic (Elasticsearch، Kibana، …).

بعد ذلك يظهر <span dir="ltr">EXTERNAL-IP</span> (حسب مزود السحابة — قد يكون له تكلفة).

### ملاحظات عند تخصيص الخدمة

| الموضوع | الشرح |
|---------|--------|
| توجيه Elasticsearch | الافتراضي يوجّه لكل النودز؛ لتحكم أدق راجع **Requests routing to Elasticsearch nodes** |
| تغيير <span dir="ltr">clusterIP</span> | حقل غير قابل للتعديل → حذف وإعادة إنشاء الخدمة → قد انقطاع قصير حتى يتحدث DNS |
| تغيير <span dir="ltr">port</span> الخارجي | اضبط <span dir="ltr">targetPort</span> على منفذ الحاوية (9200 لـ ES، 5601 لـ Kibana) |

## الوصول للـ endpoint

### من داخل الكلاستر

1. شهادة TLS من <span dir="ltr">-es-http-certs-public</span>
2. كلمة مرور <span dir="ltr">elastic</span>
3. طلب HTTPS على اسم الخدمة

```bash
NAME=hulk
kubectl get secret "$NAME-es-http-certs-public" -o go-template='{{index .data "tls.crt" | base64decode }}' > tls.crt
PW=$(kubectl get secret "$NAME-es-elastic-user" -o go-template='{{.data.elastic | base64decode }}')
curl --cacert tls.crt -u elastic:$PW https://$NAME-es-http:9200/
```

لـ Kibana: نفس الفكرة مع خدمة <span dir="ltr">-kb-http</span> والمنفذ 5601.

### من خارج الكلاستر (بعد LoadBalancer)

```bash
IP=$(kubectl get svc "$NAME-es-http" -o jsonpath='{.status.loadBalancer.ingress[].ip}')
curl --cacert tls.crt -u elastic:$PW https://$IP:9200/
```

## مواضيع متقدمة (روابط في التوثيق)

- **TLS / cert-manager** — شهادات HTTP مخصصة
- **Service meshes** — Istio، Linkerd
- **Ingress** — مع Helm أو YAML
- **توجيه الطلبات لنودز محددة** — خدمات مخصصة
